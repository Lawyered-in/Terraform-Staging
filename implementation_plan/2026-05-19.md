## 2. Infrastructure Provisions (Terraform)

We designed and created a reusable Terraform module and linked it to the root templates layer.

### A. The Bedrock Module (`modules/bedrock`)
* **`variables.tf`**: Declares environment, region, tags, and model ID configuration.
* **`outputs.tf`**: Exposes the IAM policy ARN, IAM User ARN, and AWS Secrets Manager credentials ARN.
* **`main.tf`**: Provisions the following resources:
  1. **IAM Policy (`stage-bedrock-minimax-access`)**: Limits invoke-model access exclusively to `minimax.minimax-m2.5` following the principle of least privilege.
  2. **Developer IAM User (`stage-bedrock-dev-user`)**: Standalone programmatic user for external/local developer scanning.
  3. **AWS Access Keys**: Generates long-term, non-expiring credentials for local tool access.
  4. **AWS Secrets Manager (`stage-bedrock-api-credentials`)**: Encrypts and securely stores the Access Key and Secret Key in a JSON container.

### B. Root Layer Integration (`templates/`)
* **`variables.tf`**: Defined root-level inputs for `bedrock_model_id` and `create_bedrock_iam_user`.
* **`main.tf`**: Instantiated `module "bedrock"` at the root, applying standard staging environment variables and tags.
* **`terraform.tfvars`**: Added standard variables:
  ```hcl
  bedrock_model_id        = "minimax.minimax-m2.5"
  create_bedrock_iam_user = true
  ```

## 3. Deepsec CI/CD Integration & Reporting Plan

We mapped out a solid execution strategy for integrating the scanner across all **15+ microservices** in the Lawyered platform.

### A. Pipeline Stage: BEFORE the Docker Build
We recommended executing the Deepsec security scan in the **`pre_build` phase** of AWS CodeBuild, *before* the Docker image is built.
* **Benefits:** Fail-fast mechanism (aborts build immediately if vulnerabilities exist, saving CodeBuild compute time/cost), ECR cleanliness (unsafe containers are never pushed), and alignment with SAST principles.

### B. Dual Reporting Plan (Email & Slack Alerts)
To satisfy the customer's request to receive reports on both **Email** and **Slack**, we proposed the following **Event-Driven Serverless Notification Architecture**:

```
[ CodeBuild Scan Completed ]
             ↓
 1. Copy report.html to secure S3 Bucket (s3://lawyered-deepsec-reports)
             ↓
 2. S3 fires Event Notification to AWS Lambda
             ↓
     [ AWS Lambda Function ]
    /                       \
   /                         \
[ Email via Amazon SES ]   [ Slack Webhook ]
Sends email with the S3    Posts rich message block with
report attached as HTML.   a secure pre-signed download link.
```

### C. Advanced Enterprise-Grade Reporting Alternatives
We presented five additional ways to track security audits:
1. **AWS Security Hub:** Consolidating Deepsec JSON findings directly in a centralized AWS security dashboard alongside ECR scans.
2. **GitHub Check Runs:** Blocking/approving Pull Requests directly inside the GitHub interface.
3. **CodeBuild Test Report Groups:** Rendering scan logs inside native AWS interactive graphical charts.
4. **Jira Ticket Automation:** Auto-creating security tickets on developers' sprint boards for High/Critical findings.
5. **SonarQube Dashboard Integration:** Tracking static quality and security findings on a single portal.
