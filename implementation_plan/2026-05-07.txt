# DevOps Activity Log - May 7, 2026

## 📝 Summary of Work
Today we focused on modernizing the RDS database infrastructure, optimizing costs for the staging environment, and resolving critical blockers in the CI/CD pipelines.

---

## 🛠️ Infrastructure & Code Changes

1. **RDS Map-Driven Architecture**:
   - Refactored `terraform.tfvars` and `main.tf` to use a central `rds_instances` map. This allows for multi-DB management in a single code block.
   - Added support for `allow_major_version_upgrade` in the RDS module.

2. **Database Provisioning**:
   - **lawyered-backend-new**: Created a new PostgreSQL 18.3 instance (50GB).
   - **finvica**: Optimized storage by capping `max_allocated_storage` at 100GB to reduce AWS billing.
   - **core-uat-db**: Performed a major version upgrade from PostgreSQL 15 to 18.3.

3. **Security & Secrets**:
   - Transitioned all RDS master passwords to a dynamic **AWS Secrets Manager** loop.
   - Every database now has its own isolated secret: `finvica-db-secrets`, `lawyered-backend-new-db-secrets`, etc.

4. **CI/CD Pipeline Fix**:
   - Switched Docker base images from Docker Hub to **AWS Public Gallery Mirror** (`public.ecr.aws/docker/library/node:22-alpine`) to bypass rate limits.

---

## ⚠️ Issues Faced & Resolutions

| Issue | Root Cause | Resolution |
| :--- | :--- | :--- |
| **Docker Hub 429 Error** | Pull rate limit reached for anonymous users. | Switched base images to AWS Public Mirror. |
| **InvalidParameterCombination** | Major version upgrade (15->18) requested without the `allow_major_version_upgrade` flag. | Updated RDS module to include and enable the flag. |
| **DBInstanceAlreadyExists** | Previous interrupted `apply` created the DB in AWS but not in Terraform state. | Performed a manual `terraform import` into the state. |
| **ResourceExistsException** | Secrets Manager name collision during the `for_each` refactor. | Implemented `moved` blocks in Terraform to migrate the existing resources. |
| **State Lock Error** | Interrupted process left a lock on the S3 state file. | Attempted `force-unlock`; the lock eventually cleared automatically. |
| **TypeScript Build Errors** | App code expected `password` while DB schema had `passwordHash`. | Identified as a code-level mismatch and provided a fix plan for devs. |

- **RDS Infrastructure**: Fully updated and compliant with Postgres 18.
- **Pipelines**: Fixed and running (reaching the code compilation stage).
