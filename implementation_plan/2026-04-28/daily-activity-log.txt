  Status  : RESOLVED ✅

PROBLEM STATEMENT
-----------------
  The Argo CD application "stg-admin-lawyered" was failing to sync with
  the following error:

  ERROR:
    one or more objects failed to apply, reason:
    PersistentVolumeClaim "stg-admin-lawyered-puppeteer-cache-pvc" is invalid:
    spec: Forbidden: spec is immutable after creation except
    resources.requests and volumeAttributesClassName for bound claims

  TWO PVCs AFFECTED:
  +------------------------------------------+--------+-------------------+
  | PVC Name                                 | Size   | Bound PV          |
  +------------------------------------------+--------+-------------------+
  | stg-admin-lawyered-puppeteer-cache-pvc   | 2Gi    | pvc-e95fb00c-...  |
  | stg-admin-lawyered-uploads-pvc           | 10Gi   | pvc-60b7410a-...  |
  +------------------------------------------+--------+-------------------+


ROOT CAUSE ANALYSIS (RCA)
--------------------------
  Step 1: PVCs were already BOUND to real EBS volumes in the cluster.
          Kubernetes assigns a "volumeName" when a PVC is bound:
            volumeName: "pvc-e95fb00c-e4ee-4070-a555-0c3e24931a3b"

  Step 2: The PVC manifest stored in GitHub (k8s-manifest) does NOT
          have this volumeName field — it has it as empty (""):
            volumeName: ""

  Step 3: ArgoCD compares GitHub (desired state) vs EKS cluster (actual state).
          It detects a difference:
            - GITHUB says  volumeName = ""
            + CLUSTER says volumeName = "pvc-e95fb00c-..."

  Step 4: ArgoCD tries to REPLACE the PVC using the GitHub version
          because "Replace=true" was in syncOptions.

  Step 5: Kubernetes REJECTS this because once a PVC is bound to a PV,
          its spec.volumeName field is IMMUTABLE — it cannot be changed.

  VISUAL FLOW OF THE BUG:
  +-----------------------+         +------------------+         +--------------+
  |  k8s-manifest (GitHub)|         |   Argo CD        |         |  Kubernetes  |
  |  volumeName: ""       | ------> | Sees diff!       | ------> | REJECTED!    |
  |                       |  diff   | Tries to replace |  apply  | spec is      |
  |                       |         | PVC with ""      |         | immutable    |
  +-----------------------+         +------------------+         +--------------+


FIRST FIX ATTEMPTED (Partial — Did Not Work Alone)
---------------------------------------------------
  Added "ignoreDifferences" to tell ArgoCD to ignore the volumeName field
  during the COMPARISON phase:

  FILE: resources/argocd-manifests/admin-lawyered.yaml

    ignoreDifferences:
      - group: ""
        kind: PersistentVolumeClaim
        jsonPointers:
          - /spec/volumeName   # <-- ignore this field when comparing

  WHY IT STILL FAILED:
    ignoreDifferences only affects DETECTION. When any sync is triggered
    (due to a new image tag), ArgoCD still sends the full PVC manifest
    (with volumeName: "") to Kubernetes using "kubectl replace".
    Kubernetes rejects this because volumeName is immutable.


FINAL FIX — WORKING SOLUTION ✅
---------------------------------
  Replaced "Replace=true" with "ServerSideApply=true" in syncOptions.

  EXPLANATION:
    - Replace=true  : uses "kubectl replace" → sends FULL manifest → fails
                      on immutable fields
    - ServerSideApply=true : uses server-side apply → only applies fields
                             you OWN → leaves volumeName untouched by k8s

  FILE CHANGED: resources/argocd-manifests/admin-lawyered.yaml

  BEFORE:
  -------
    syncPolicy:
      automated:
        prune: true
        selfHeal: true
      syncOptions:
        - CreateNamespace=true
        - PrunePropagationPolicy=foreground
        - PruneLast=true
        - Replace=true          <-- THIS CAUSED THE PROBLEM

  AFTER:
  ------
    ignoreDifferences:          <-- ADDED: ignore volumeName during compare
      - group: ""
        kind: PersistentVolumeClaim
        jsonPointers:
          - /spec/volumeName
    syncPolicy:
      automated:
        prune: true
        selfHeal: true
      syncOptions:
        - CreateNamespace=true
        - PrunePropagationPolicy=foreground
        - PruneLast=true
        - ServerSideApply=true  <-- CHANGED: safer apply method

WHAT IS ECR?
-----------
  AWS ECR is a fully managed container registry. When CodeBuild builds a
  Docker image, it pushes it to ECR. Kubernetes (EKS) pulls from ECR
  when deploying the container.

  FLOW:
    Developer pushes code
        |
        v
    CodeBuild builds Docker image
        |
        v
    ECR stores image (344367180480.dkr.ecr.ap-south-1.amazonaws.com/<name>)
        |
        v
    EKS pulls image from ECR and runs it

FULL CI/CD FLOW AFTER COMPLETION
----------------------------------
  This is how a deployment will work end-to-end for each new service:

  1. Developer pushes code to GitHub branch (development-branch / develop)
           |
           v
  2. GitHub webhook notifies AWS CodeStar Connection
           |
           v
  3. AWS CodePipeline SOURCE stage pulls the code
           |
           v
  4. AWS CodeBuild BUILD stage runs:
       a. Logs in to ECR
       b. Builds Docker image (using Dockerfile in repo root)
       c. Pushes image to ECR with tag = first 7 chars of commit hash
       d. Fetches SSH key from AWS Secrets Manager
       e. Clones k8s-manifest repo via SSH
       f. Runs sed to update image tag in deployment.yaml
       g. Git commit + push back to k8s-manifest staging branch
           |
           v
  5. ArgoCD polls k8s-manifest (staging branch) every ~3 mins
           |
           v
  6. ArgoCD detects image tag change in deployment.yaml
           |
           v
  7. ArgoCD syncs — applies updated deployment.yaml to EKS
           |
           v
  8. EKS pulls new image from ECR and rolls out new pods


  +-----------------+    push     +-----------+   webhook   +-------------+
  | GitHub          | ----------> | CodeStar  | ----------> | CodePipeline|
  | (dev branch)    |             | Connection|             |             |
  +-----------------+             +-----------+             +------+------+
                                                                   |
                                                                   | triggers
                                                                   v
  +-------------+   SSH push   +-------------+   build    +-------+------+
  | k8s-manifest| <----------- | Secrets Mgr | <--------- | CodeBuild    |
  | deployment  |   image tag  | SSH key     |   ECR push |              |
  | .yaml update|              +-------------+            +--------------+
  +------+------+
         |
         | ArgoCD polls
         v
  +-------------+   sync     +-------+
  | ArgoCD      | ---------> |  EKS  |
  | detects     |            | pods  |
  | change      |            | update|
  +-------------+            +-------+
