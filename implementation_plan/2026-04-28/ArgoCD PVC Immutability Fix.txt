--------------------------------------------------------------------------------
1. WHAT IS THE ISSUE?
--------------------------------------------------------------------------------

When Argo CD tried to sync the "stg-admin-lawyered" application, it threw
the following error:

  ERROR:
  -------
  one or more objects failed to apply, reason:
  error when replacing "/dev/shm/1921066185":
  PersistentVolumeClaim "stg-admin-lawyered-puppeteer-cache-pvc" is invalid:
  spec: Forbidden: spec is immutable after creation except
  resources.requests and volumeAttributesClassName for bound claims

  DIFF SHOWN BY ARGO CD:
  ------------------------
  - "VolumeName": "pvc-e95fb00c-e4ee-4070-a555-0c3e24931a3b",
  + "VolumeName": "",

  Two PVCs were affected:
    - stg-admin-lawyered-puppeteer-cache-pvc  (2Gi)
    - stg-admin-lawyered-uploads-pvc          (10Gi)


--------------------------------------------------------------------------------
2. WHY DOES THIS HAPPEN? (ROOT CAUSE)
--------------------------------------------------------------------------------

Step-by-step explanation:

  a) When a PersistentVolumeClaim (PVC) is first created in Kubernetes, it gets
     BOUND to a real EBS volume (PersistentVolume). At that point, Kubernetes
     assigns a "volumeName" to the PVC (e.g., "pvc-e95fb00c-...").

  b) The PVC manifest stored in the k8s-manifest GitHub repo does NOT have this
     volumeName field — it has it empty ("").

  c) Argo CD compares what is in GitHub (desired state) vs what is running in
     the cluster (actual state). It sees a difference:
       - GitHub says volumeName = ""
       - Cluster says volumeName = "pvc-e95fb00c-..."

  d) Argo CD tries to REPLACE the PVC with the GitHub version (because we have
     "Replace=true" in syncOptions).

  e) Kubernetes REJECTS this because once a PVC is bound, its "spec.volumeName"
     field is IMMUTABLE — it cannot be changed.

  Result: Sync Fails with "spec is immutable" error.


--------------------------------------------------------------------------------
3. ARCHITECTURE — HOW ARGO CD SYNC WORKS
--------------------------------------------------------------------------------

  DEVELOPER PUSH
       |
       v
  GitHub: k8s-manifest
  (staging branch)
  deployments/
  └── stg-admin-lawyered/
      ├── deployment.yaml       <-- PVC has volumeName: ""
      ├── service.yaml
      └── pvc.yaml
       |
       v
  ARGO CD POLLS every 3 mins
       |
       v
  COMPARE: GitHub (desired) vs EKS Cluster (actual)
       |
       |--- deployment.yaml  -> CHANGED (new image tag) -> SYNC OK ✅
       |--- service.yaml     -> NO CHANGE               -> SYNC OK ✅
       |--- pvc.yaml         -> volumeName DIFFERS      -> SYNC FAIL ❌
       |                        (GitHub="" but Cluster="pvc-e95fb0...")
       v
  Kubernetes API
       |
       v
  REJECT: "spec is immutable after creation"

  RESULT: Entire sync marked as FAILED even though deployment updated fine.


--------------------------------------------------------------------------------
4. WHAT IS THE FIX?
--------------------------------------------------------------------------------

We add an "ignoreDifferences" block to the Argo CD Application manifest.
This tells Argo CD:
  "When comparing desired vs actual state, IGNORE the volumeName field on PVCs."

This way Argo CD will:
  - Still sync the Deployment (new image tag) ✅
  - Still sync the Service ✅
  - SKIP comparing or modifying PVC volumeName ✅


--------------------------------------------------------------------------------
5. THE CODE CHANGE
--------------------------------------------------------------------------------

FILE CHANGED:
  resources/argocd-manifests/admin-lawyered.yaml

BEFORE (original):
------------------
  spec:
    project: default
    source:
      repoURL: git@github.com:Lawyered-in/k8s-manifest.git
      targetRevision: staging
      path: deployments/stg-admin-lawyered
    destination:
      server: https://kubernetes.default.svc
      namespace: stg
    syncPolicy:
      automated:
        prune: true
        selfHeal: true
      syncOptions:
        - CreateNamespace=true
        - PrunePropagationPolicy=foreground
        - PruneLast=true
        - Replace=true
    revisionHistoryLimit: 3


AFTER (with fix):
-----------------
  spec:
    project: default
    source:
      repoURL: git@github.com:Lawyered-in/k8s-manifest.git
      targetRevision: staging
      path: deployments/stg-admin-lawyered
    destination:
      server: https://kubernetes.default.svc
      namespace: stg
    ignoreDifferences:                      <-- ADDED THIS BLOCK
      - group: ""
        kind: PersistentVolumeClaim
        jsonPointers:
          - /spec/volumeName               <-- IGNORE this field during compare
    syncPolicy:
      automated:
        prune: true
        selfHeal: true
      syncOptions:
        - CreateNamespace=true
        - PrunePropagationPolicy=foreground
        - PruneLast=true
        - Replace=true
    revisionHistoryLimit: 3

--------------------------------------------------------------------------------
8. NOTES & LESSONS LEARNED
--------------------------------------------------------------------------------

  a) The "Replace=true" sync option in Argo CD causes it to use
     kubectl replace (not apply). This is stricter and hits immutability
     limits more often.

  b) PVC volumeName is ALWAYS immutable after binding. Any PVC manifest
     stored in Git should always use ignoreDifferences for this field.

  c) If this same error appears for OTHER services that have PVCs, apply
     the same ignoreDifferences block to their respective ArgoCD yaml files.

  d) The Deployment itself WAS syncing successfully even during the error
     (image tag was being updated). The error only blocked Argo CD from
     marking the overall sync as "Succeeded".
