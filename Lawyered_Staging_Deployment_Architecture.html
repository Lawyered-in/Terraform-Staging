1. Executive Summary

The Lawyered staging environment runs on AWS and is fully managed via Terraform (Infrastructure as Code). The platform hosts 19 microservices across 4 GitHub organizations, deployed into an Amazon EKS cluster using a GitOps workflow powered by Argo CD.

CI/CD is handled by AWS CodePipeline + CodeBuild, with Docker images stored in Amazon ECR. Secrets are managed through AWS Secrets Manager with External Secrets Operator (ESO) syncing them into Kubernetes. All pipelines include an optional DevSecOps security scanning stage.

7.2 Detailed Build Process

Stage 1 — Source

  • GitHub webhook triggers pipeline on push to the configured branch
  • Uses AWS CodeConnections (separate connections per GitHub org)

Stage 2 — Build (CodeBuild)

  1. Pre-pull Docker base images (e.g., node:20-alpine) to avoid Docker Hub rate limits
  2. Build Docker image with environment-specific build args (API URLs, keys, etc.)
  3. Tag image with latest and unique IMAGE_TAG (commit SHA)
  4. Push both tags to ECR

Stage 3 — Security Scan (DevSecOps)

  • Enabled on all current services (enable_security_scan = true)
  • Uses dedicated devsecops-role IAM role
  • Reports stored in S3 bucket devsecops-reports-storage-bucket
  • Slack alerts via webhook (devsecops/slack-webhook secret)

Stage 4 & 5 — Manifest Update (Post-Build)

  1. Clone Lawyered-in/k8s-manifest repo (staging branch) using SSH key from Secrets Manager
  2. Update deployment.yaml image tag via sed
  3. Update migration-job.yaml if applicable (backend services with DB migrations)
  4. Commit and push changes back to staging branch

Stage 6 — ArgoCD Auto-Sync

  • ArgoCD watches k8s-manifest repo (staging branch)
  • Detects manifest changes → auto-syncs with prune: true and selfHeal: true
  • Deploys updated pods into stg namespace on EKS

15. Quick Reference for Developers

How to Deploy Your Code

  1. Push your changes to the correct branch (see Application Matrix, Section 6.1)
  2. Monitor the CodePipeline in AWS Console → CodePipeline
  3. Check ArgoCD at https://argocd-staging.lawyered.in for sync status
  4. Verify your pods: kubectl get pods -n stg | grep <service-name>

How to Access the EKS Cluster

# 1. Configure AWS SSO credentials
aws sso login --profile <your-profile>

# 2. Update kubeconfig
aws eks update-kubeconfig --name eks-cluster-np --region ap-south-1

# 3. Or use bastion (via EICE)
aws ec2-instance-connect ssh --instance-id i-0bdd7be4291bab7bb

How to Check Logs

# Pod logs
kubectl logs -n stg deployment/<service-name> -f

# ArgoCD app status
kubectl get application -n argo-cd <app-name> -o yaml

How to Add a New Microservice

  1. Create ECR repository entry in terraform.tfvars → ecr_repositories
  2. Add pipeline config in terraform.tfvars → codepipelines
  3. Create ArgoCD manifest in resources/argocd-manifests/stg-<service>.yaml
  4. Add K8s deployment manifests to k8s-manifest repo under deployments/stg-<service>/
  5. Run terraform plan and terraform apply
💡 Tip Backend services with database migrations should include custom_post_build_commands that update both deployment.yaml and migration-job.yaml in the k8s-manifest repo.
